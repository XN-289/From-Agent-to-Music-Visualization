# 使用与开发流程

本文档是当前用户手册。一个新会话只按本文档，应能完成本地启动、生成歌曲、调整并保存视觉期待、推送到 Folia，以及用现有 Electron 能力导出横屏与竖屏视频。

当前需求源是 [tasks/prd-agent-music-visual-studio.md](../tasks/prd-agent-music-visual-studio.md)。实现、测试、文档或排期与它冲突时，以 PRD 为准，并先修订 PRD 与 [decisions.md](../decisions.md)。当前项目状态见 [PROJECT_STATE.md](../PROJECT_STATE.md)。

## 1. 端口与目录

| 服务 | 默认地址 | 说明 |
|---|---|---|
| Electron 开发服务 | `http://127.0.0.1:3000` | 一键启动的内部开发服务 |
| Music Agent | `http://127.0.0.1:3003` | Studio 入口是 `/studio` |
| Folia web | `http://127.0.0.1:3004` | 供 Studio 构图预览使用 |
| Folia Stage API | `http://127.0.0.1:32107` | 由 Electron 端实际显示的端口和 token 为准 |

一键启动默认使用下表端口。若端口被未知进程占用，启动脚本会列出占用者并拒绝接管；不要直接结束未知进程。实际端口以配置为准。

```text
music-agent/   Next.js + pi Agent + 音乐 Provider 兼容层
folia-major/   Folia 播放器、Stage API、Electron 导出
docs/          当前手册与历史资料
tasks/         PRD 与验收记录
```

## 2. 首次准备

要求 Node.js 24 或更高版本。music-agent 使用 pnpm，Folia 使用 npm。

```powershell
Push-Location music-agent
pnpm install
Copy-Item .env.example .env.local
pnpm db:push
Pop-Location

Push-Location folia-major
npm install
Copy-Item .env.example .env.local
Pop-Location
```

编辑 `music-agent/.env.local`：

```env
# LLM：直连 DeepSeek，或配置 OpenAI 兼容中转站
DEEPSEEK_API_KEY=

# 真实生成默认使用公司统一音乐代理；mock 用于免费离线验收
SUNO_PROVIDER=musicproxy
MUSIC_PROXY_BASE_URL=http://127.0.0.1:8800
MUSIC_PROXY_API_KEY=
MUSIC_PROXY_DEFAULT_PROVIDER=suno_openaihk
MUSIC_PROXY_MODEL=auto

# Folia
FOLIA_STAGE_BASE_URL=http://127.0.0.1:32107
FOLIA_STAGE_TOKEN=
FOLIA_WEB_URL=http://127.0.0.1:3004
MUSIC_AGENT_ORIGIN=http://127.0.0.1:3003
```

不要把密钥写入 Git。修改 `.env.local` 后需要重启 Music Agent。

新设备或首次使用时，还需要完成一次 Stage 配对：按第 3.4 节启动 Folia Electron，在设置中开启 `Stage Mode` 并选择 `Stage API`，把界面显示的 Bearer token 写入 `FOLIA_STAGE_TOKEN`；确认 `/stage/health` 通过后停止手动服务。之后日常使用第 3.1 节一键启动，不需要每次手工配对。

## 3. 启动与停止

### 3.1 一键启动

完成第 2 节首次准备后，在仓库根目录双击：

```text
启动Studio.cmd
```

或执行：

```powershell
node scripts/start-studio.mjs
```

脚本会按顺序启动 Music Agent、Folia web、Electron 开发服务与 Folia Electron，并对四个服务做语义健康检查：

| 服务 | 检查 |
|---|---|
| Music Agent | `/studio` 返回 HTML，且包含 Music Agent 与 Next.js 标记 |
| Folia web | 首页返回 HTML，且包含 Folia 与 root 挂载点 |
| Electron dev server | 首页返回 HTML，且包含 root 挂载点 |
| Folia Stage | `/stage/health` 返回 `enabled=true`、`modeEnabled=true`、`source=stage-api` |

全部通过后自动打开 `http://127.0.0.1:3003/studio`。

启动脚本把运行态写入 `.runtime/studio-services.json`，日志在 `.runtime/logs/<runId>/`，只保留最近 10 次启动日志。失败时会停止本次已启动且仍归属本仓库的进程，写入失败状态与日志，并显示三个处理动作：重试、打开日志、停止全部。

### 3.2 复用、重启与端口占用

如果上次启动的健康服务仍在，脚本会提示：

- `R`：复用健康服务；
- `S`：停止上次记录的本仓库进程后重启。

也可直接执行 `node scripts/start-studio.mjs --reuse` 复用。脚本只复用状态文件记录、进程归属仍在本仓库、且四个语义健康检查都通过的服务。

如果端口由未知进程占用，脚本会显示端口、PID、进程名与命令行，但不会结束它。请先自行确认并关闭占用者。若确实需要换端口，必须同步更新相关配置和启动脚本；不要只改一个服务。

### 3.3 停止

在仓库根目录双击：

```text
停止Studio.cmd
```

停止脚本只处理 `.runtime/studio-services.json` 记录、且当前命令行或可执行路径仍归属本仓库的进程；不会按端口清理未知进程。

### 3.4 手动启动（仅调试）

一键启动失败、需要观察单个服务日志或复现开发脚本行为时，才使用以下命令。日常不要同时叠加一键启动与手动启动。

#### 启动 Folia Electron 并开启 Stage

```powershell
Push-Location folia-major
npm run dev:electron
Pop-Location
```

在 Folia 设置中开启 `Stage Mode`，来源选择 `Stage API`，记下界面显示的端口和 Bearer token。默认 Stage 端口是 `32107`；若实际显示不同，必须回填 `FOLIA_STAGE_BASE_URL`。

#### 启动 Folia web

另开一个终端：

```powershell
Push-Location folia-major
npm run dev -- --host 127.0.0.1 --port 3004 --strictPort
Pop-Location
```

这个端口用于 Studio 右侧构图预览。Electron dev 自身的开发页面仍使用其脚本默认端口，不影响 Studio 按配置访问 3004。

#### 启动 Music Agent

```powershell
Push-Location music-agent
pnpm dev --port 3003
Pop-Location
```

健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:3003/studio
Invoke-RestMethod http://127.0.0.1:32107/stage/health
```

`/stage/health` 应返回 `enabled=true`、`modeEnabled=true`、`source=stage-api`。然后打开 `http://127.0.0.1:3003/studio`。

## 4. 生成歌曲

1. 打开 Studio，确认顶部 Provider 标签是 `真实生成` 或 `Mock 生成`。
2. 在中间对话栏新建或继续会话，描述主题、情绪、语言和画面期待，例如“写一首夏日夜晚的日文抒情歌，副歌像烟花散开”。
3. Agent 会先做需求挖掘，再进入写词与生成阶段；日文或非中文主语言会生成逐行中文翻译。
4. 生成完成后，产物写入 `music-agent/data/media/<songId>/`，包括音频、`lyrics.lrc`、必要时 `lyrics.t.lrc`、封面和 `meta.json`。
5. Stage 可用时会自动推送；失败不会中断生成，左侧或顶部显示待重推时，可点击 `推送舞台` 手动恢复。

真实 Provider 会消耗生成额度。只想验证链路时，使用本文第 9 节的 Mock 附录；不要为了文档检查或 UI 回归调用真实音乐 Provider。

## 5. 调整视觉期待

Studio 右侧就是当前歌曲的视觉期待区：

1. 选择 `夏夜霓虹`、`雨窗民谣` 或 `Livehouse 现场`。
2. 拖动 `能量`（0-100）、`色温`（-20 到 20）、`高潮氛围`（0-100）。
3. 卡片会直接显示色卡、预设名、语义标签（例如“高能量 · 冷色 · 强副歌”），以及与已保存配方的具体差异。
4. 构图预览会随草稿防抖更新；音频反应和最终观感仍以 Folia 真实播放为准。
5. 点击 `保存期待`，状态从“未保存”变为“已保存”后才算落库。

数据库列名是 `visual_recipe`，API 与前端属性名是 `visualRecipe`；它们是同一份数据的存储名和序列化名。保存后的配方会随歌曲推送为 Stage `visualConfig`，只覆盖当前 Stage 会话，不污染 Folia 全局偏好。

## 6. 播放与推送

1. 在 Studio 点击 `推送舞台`，确认请求成功。
2. 在 Folia Electron 播放该歌曲，检查封面、主歌词、中文翻译副字幕与视觉配方。
3. 切歌、清空 Stage 或新会话后，配方不应继承到下一首；无配方歌曲应恢复本地外观。
4. 若 Stage 停止，生成可以继续完成；Stage 恢复后在 Studio 或歌曲详情页重推。

## 7. 导出横屏与竖屏

当前可使用 Folia 已有 Electron 导出能力，分两次导出：

1. 确认配方已保存并已推送到 Folia。
2. 在 Folia 主窗口打开命令面板，执行 `切换遥控窗口`。
3. 在遥控窗口点击视频导出图标，进入 `视频导出`。
4. 选择 `整首歌`，分别选择 `1920 x 1080` 与 `1080 x 1920`。
5. 点击开始录制，选择保存位置，等待进度到完成；第二个方向重复同样操作。
6. 导出文件必须是 MP4 / H.264 / AAC，画面不得包含 Music Agent 聊天 UI。

这是当前手动能力说明，不代表 US-004 已验收。US-004 要求一个任务串行产出两段视频并提供统一进度、失败处理、文件登记与校验；在 PRD 验收矩阵更新前，不要把手动探针宣称为正式导出完成。

## 8. 常见问题

- **Studio 预览失败**：先确认 3004 的 Folia web 可打开，再确认 `FOLIA_WEB_URL`。预览进入失败态时可点击重试。
- **推送失败**：确认 Folia Electron 已开启 Stage Mode，来源为 Stage API，端口和 token 与 `.env.local` 一致，并重启 Music Agent。
- **副字幕不显示**：Mock WAV 只验证 `lyrics.t.lrc` 与推送；真实 MP3 可用 `node scripts/check-metadata.mjs "data/media/<songId>/audio-01-*.mp3"` 检查双 USLT。
- **时间轴错位**：记录歌曲 ID、主歌词与翻译的时间戳，对照 `lyrics.lrc` 与 `lyrics.t.lrc`；不要手动改生成产物掩盖问题。
- **端口被占用**：不要直接结束未知进程。先确认占用者；如必须换端口，同步更新 `FOLIA_WEB_URL`、`MUSIC_AGENT_ORIGIN` 或 Stage URL。

## 9. 免费 Mock 验收附录

该流程只用于离线验证，不消耗音乐 Provider 额度。

终端 A：

```powershell
Push-Location folia-major
node test/manual/stage-api-dev.cjs --sync-env
Pop-Location
```

终端 B：

```powershell
Push-Location music-agent
$env:SUNO_PROVIDER='mock'
$env:DB_PATH=(Join-Path (Get-Location).Path 'data/music-agent-mock.db')
$env:MEDIA_OUTPUT_DIR='data/media-mock'
$env:FOLIA_STAGE_BASE_URL='http://127.0.0.1:32107'
pnpm db:push
pnpm dev --port 3003
Pop-Location
```

打开 `http://127.0.0.1:3003/studio`，顶部应显示 `Mock 生成`。生成后检查 `music-agent/data/media-mock/<songId>/`。关闭 Stage 后生成仍应完成并显示待重推；恢复 Stage 后手动重推应成功。
